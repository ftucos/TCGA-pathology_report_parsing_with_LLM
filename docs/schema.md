# Simple bladder report extraction

The model returns one JSON object with only four fields:

```json
{
  "stage": "pT2b pN0",
  "grade": "high grade",
  "histology": "urothelial carcinoma",
  "margins": "Negative resection margins"
}
```

All four fields are free text or `null`. Missing keys default to `null`; whitespace-only
strings become `null`. Unexpected extra keys are ignored. If the model returns a
number, list or object for a field, it is preserved as JSON text rather than rejected.
The generation schema requests strings/nulls to keep normal responses simple.
Malformed JSON or a non-object response still triggers a retry, as does incomplete
model generation. There are no CAP completeness requirements, evidence quotes,
page citations, staging enums, grade enums or node-count consistency checks.

| Field | Requested content |
| --- | --- |
| `stage` | Reported bladder stage/TNM or stage group, retaining prefixes. If unstaged but invasion is described, retain that description and say the stage is not stated. |
| `grade` | Reported wording, including legacy grades, differentiation or mixed grade. |
| `histology` | Tumor type, relevant variants and mixed components. |
| `margins` | Reported margin status and sites, retaining mixed or uncertain findings. |

The prompt distinguishes bladder findings from an independent prostate cancer.
Missing margins are `null`, not an assumed negative. Uncertainty, conflicts and
multiple specimens are retained briefly in the affected strings. There is no
automatic conversion of invasion descriptions to numeric stage, no conversion
of differentiation to binary grade, and no CAP-based normalization step.

`docs/bladder.schema.json` is generated by `blca schema`. The schema version `2.0`
is stored by the application in result metadata, not requested from the model.
The synthetic example in `docs/example.extraction.json` demonstrates the output.

The CSV has one row per successfully processed report, with columns:
`report_id, case_id, filename, stage, grade, histology, margins`.
This includes reports whose four values are all null (empty CSV cells).
JSONL retains these findings inside `extraction`, alongside source/model provenance
and the OCR checkpoint reference. Original OCR and raw model responses remain
available for comparison with TCGA metadata and manual review.

The new schema/prompt invalidates previous extraction results. Rerun `run` without
`--force` to reuse matching OCR and regenerate the four-field extraction. Older
archived results are retained but not exported as new-schema results. Regenerate
the exports after processing; do not mix old specimen-level CSV rows with the new
report-level rows. The 413 reports represent 412 cases, so case ID is not unique.
